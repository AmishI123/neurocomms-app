# Twelve fictional saved-draft journeys

All people and wording below are fictional. These examples describe intended behavior, not participant findings.

## 1. Write now, finish tomorrow

Alex selects an unanswered question and builds a message. After editing the wording, Alex chooses Save draft on this device and reads the private-saving explanation. Only confirming keeps it. The app does not send anything or change the question's state. Later edits need another explicit save. Tomorrow, Alex opens the saved-draft list from Home and chooses that message; it does not open automatically.

## 2. Keep a progress entry without claiming it happened

Rae chooses Waiting for reply, adds a date and starts a private note. Rae saves it as a draft, not as follow-up progress. The saved visit still has its previous state and history. Returning later restores the exact fields. Save follow-up records the entry and removes that saved draft in one successful operation. A failed operation must do neither.

## 3. Change your mind before saving

Kim edits a temporary message, opens the save explanation and chooses Return to draft. No saved data changes. The working message still exists in the open page. Kim can download a private draft backup or save later. Closing the page without either can lose that temporary work; browser-close warnings are not guaranteed on phones.

## 4. Edit a saved draft without updating its saved copy

Jo reopens a saved message, changes a sentence and closes its dialog. The new words remain in this page, but the old saved copy is unchanged. Home offers a return to the working message and says the work is temporary or unsaved. Save draft on this device updates the saved copy only after a successful write. Discarding the working editor does not delete the saved draft.

## 5. The original item changed

Dev saves a progress draft. Later, the original question gets a new private answer or progress event. Reopening the draft keeps its earlier fields and explains that the original changed. Trying to record it must not overwrite newer work. Dev can keep or download the old draft and deliberately start a new entry from current saved work. The app does not quietly update the old draft's starting point.

## 6. The original visit was deleted

Lee deletes a saved visit but has an independent saved message and progress draft. Those drafts remain and may contain earlier words. Their list explains the difference. The message can still be edited or downloaded. The progress draft cannot be applied to a different item just because its words look similar. Lee can delete each saved draft separately; downloaded files remain outside the app.

## 7. Two tabs contain different edits

Noor opens a draft in two tabs. One tab saves new wording first. The other must not overwrite it or delete it as a side effect of recording older progress. The older working text remains available for a private backup. Noor reloads saved data only after protecting any words that have not been saved. A newer saved copy is not silently chosen over unsaved editor content.

## 8. Storage fails or another tab is busy

Sam confirms a draft save, but the browser cannot write. The editor says not saved and keeps its exact text. Retrying does not create repeated drafts. If the write is waiting on another tab and Sam closes the dialog, that queued save is cancelled before it can write later. Cancelling a queued finish or delete also preserves the stored draft and original visit.

## 9. Restore a private draft backup

Ash downloads the structured private draft backup, which can reopen its fields, unlike a plain-text message download. Restoring first shows a preview and asks before saving. A draft-only file does not carry trusted source-visit links to this browser, so restored progress remains readable but is not attached to a guessed local item. Use full device transfer to bring visits and linked drafts together. Different copies remain separate; an identical restored copy is skipped.

## 10. Move the saved draft with its visit

Tari saves a progress draft, opens device transfer and checks that the saved draft is included. Unsaved later edits are excluded unless saved first. On the receiving browser, Tari reviews the visit and draft before importing. If the receiving browser has a different version, both versions stay separate and the draft points to the version that travelled with it. It can be resumed offline. Recording there does not change the original browser.

## 11. Open a different draft without losing the current words

Jules has unsaved edits in one message, then chooses another saved draft. The app offers a return to the current message or an explicit discard of its working edits. It does not silently switch editors. Even after discarding those edits, the earlier saved copy remains in the list. Deleting a saved draft requires its own confirmation and cannot erase separate working edits.

## 12. Close the browser and return offline

Morgan saves a draft and waits until offline app files are ready, then closes the entire browser. On reopening offline, Home shows only the saved-draft count. Morgan chooses a draft explicitly and finds the same words. Keyboard controls and narrow/enlarged layouts must still work. This is the shared web app; no physical Android/iPhone or screen-reader result is implied by the browser checks.
