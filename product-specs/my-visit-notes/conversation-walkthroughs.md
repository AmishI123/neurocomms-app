# Conversation-view walkthroughs

These are fictional software journeys, not participant accounts. Names and visit wording are examples. They make no claim about a diagnosis or a clinical outcome.

## 1. A question without the private preparation

Sam writes two questions and a private reminder. Sam opens “Choose words for conversation view”, selects only the first question and previews it. The display shows that question, not the reminder, visit title, library or second question. Sam hides it before taking the device back. Leaving requires a choice that explains private workspace content can appear. Sam records a personal answer, returns through preview, and still sees only the question. After the visit, the existing review holds the question and answer separately. The answer is not selected for sharing automatically.

## 2. Asking for time

Jo selects a question and edits an optional request to “Please wait while I write my answer.” The preview shows both pieces of wording. During the conversation Jo opens “Show a request” and chooses that message. It replaces the question. “Return to question” restores the same question. Neither action marks anything answered. The edited request lasts for this page session; it is not silently saved as a reusable request.

## 3. Requests without questions

Lee starts an empty visit and selects “Please write that down.” A question is not required. After showing the request, Lee deliberately returns to preparation or the existing review. The exit does not offer a personal answer note for a question that was never selected. No question is created just to satisfy the display.

## 4. Interrupted before answering

Ari shows the second chosen question and presses Escape. The words disappear; the private workspace stays hidden. Resume restores the same question. Switching away from an active display should also hide it, but operating-system screenshots and app-switcher previews are outside this app's control. A reload does not reopen the conversation display. A saved visit retains its last successfully saved current question; temporary choices and edited messages do not survive closing.

## 5. Storage fills up

Dev saves a visit, then storage becomes unavailable. Moving to another question still works in memory. On hiding or leaving, the message says changes are not saved and directs Dev back to the workspace for a save or download. The app must not claim the old saved question position is the new one. Dev resumes and sees the in-memory question. The previous saved record stays intact.

## 6. A save takes time

Another tab temporarily holds the browser's save lock. Morgan moves to the next selected question and hides the display. The status says changes are not saved. When the lock becomes available and the write finishes, the paused status changes to saved without needing to reveal the question. If the page closes before saving finishes, the last successful saved copy is the only promised copy.

## 7. Another tab changes the visit

Ren is displaying a question when another tab changes saved notes. The display hides and reports a conflict. Ren can keep the in-memory wording for the conversation, but it must not overwrite the other tab's work. Before closing, Ren deliberately returns to the private workspace and uses the existing backup/recovery choices. This is not automatic syncing or merging.

## 8. Wording changes before returning

Kit leaves the display, changes a question in preparation and reopens conversation setup. The previous permission to show old wording does not automatically approve the new wording. Choices start unchecked and the new text needs another preview. Personal answer edits do not alter the selected question text and must not pull the answer into the preview.

## 9. Keyboard, long wording and reading choices

Ash uses the keyboard to move among display controls. Focus stays in the modal, and Escape hides instead of exposing the workspace. Long words wrap at narrow width. Existing large-text, spacing and contrast choices apply. Printing while in conversation view must not print a previous private summary. These browser checks do not replace a screen-reader or physical-phone review.

## 10. Offline appointment

Pat first opens the app online and waits for offline setup. Pat saves a fictional visit, then reopens without a connection. The saved visit can enter conversation view, hide, resume and return to review. Offline setup is not a backup: clearing browser data can still remove notes. Device transfer and full backups remain separate, deliberate actions.
