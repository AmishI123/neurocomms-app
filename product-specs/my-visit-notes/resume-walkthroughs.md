# Save and resume — fictional walkthroughs

These examples are invented software-check material, not participant accounts.

## Pause before deciding what to add

Open Bring existing notes. Paste a few appointment questions. Select a passage, make it a question, and edit the chosen wording. Give the preparation a name such as “Questions for next week.” Choose Save this preparation on this device, read what it includes, and confirm.

The preparation status now says it is saved. Editing again changes that message to not saved. Choose save again before leaving. Preparation does not save itself after every edit, and saving it does not separately save a visit.

Close the browser. Reopen the app, open Saved preparations, and resume the named preparation. The source, edited choices, types and destination are restored. Empty passages left unfinished are kept too; correct or remove them before confirming additions.

## Finish after returning offline

Wait for offline app files to be ready before disconnecting. Reopen the saved preparation without a connection. Review and confirm additions to a new temporary visit.

The completion record and resulting draft are saved together inside preparation. They do not create a separately saved visit yet. If you close the browser now, resume the preparation and choose Open last completed result. The earlier passages are not added again. Save the visit separately when ready.

## The destination changed while you were away

Save preparation aimed at an existing saved visit. Later, change that visit's title or questions. Resume preparation and choose review. The app explains that the destination changed and shows additions against its current content. Check matches and wording before confirming.

If someone deleted the saved visit, review stops and asks for an available destination. Opening another visit does not redirect preparation to that other record.

## Saving fails

If saving preparation fails, keep the page open. Download private preparation backup. It includes source, edited choices and any retained draft context—not just the original source text.

If a completed-batch write fails, the previous saved preparation and visit remain unchanged. The pending selections remain available for review. Resolve the storage problem and review again. Do not assume a success message from an earlier save protects later edits.

## Recover from a backup

Open Saved preparations and use Restore a private preparation backup. Review its name and pending/completed counts before opening. It opens as temporary preparation; saving is still your choice. Existing saved preparations and the open visit are not overwritten.

A completed backup preserves its completed state and result. Saving it also retains the completion identifiers. On that browser, restoring an older pending backup for the same recorded batch does not add it again. If the original result is still available, open it instead.

A browser with only an old pending backup cannot know about later work done elsewhere. Review the destination and matching text; the app does not promise cross-device history without the relevant records.

## Clean up separately

Once the visit is separately saved, you may delete its preparation from Saved preparations. Read the warning and confirm. The visit stays intact. Preparation source, pending choices and retained draft/result copies are removed from the saved preparation and, if currently open, from this page.

If the result exists only inside preparation, deleting preparation loses that result. Open it or keep a private backup first. Minimal completion identifiers remain to block accidental replay of an old backup; they contain no source text.

Clearing source and choices in the working area is not deletion of a saved copy. Save the cleared state if you want to keep that change. Clearing saved visits also does not delete saved preparations: delete them separately if needed.

## Privacy reminder

Preparation and visit-library backups are different files. Visit-library backups do not include preparation. A complete preparation backup may contain private source text and draft copies that should never enter a shared summary. Files are unencrypted; store them privately. No account, upload, medical interpretation or cloud recovery is provided.
