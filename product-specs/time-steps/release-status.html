What is ready, and what is not

Run the technical-preview check

From communication-tool/, use the host browser-library path available on your machine:

PHRASE_STUDIO_BROWSER_LIBS=/path/to/browser-libs \
  npm run time-steps:release-candidate

This rebuilds the mobile bundle and Android debug APK, runs the scoped browser and accessibility checks, audits the APK, creates the handoff archive, and verifies every packaged file hash.

Refresh the advisory judge

The stored LLM judge is advisory and must be regenerated after evidence changes. Run this check:

npm run time-steps:judge-freshness

It currently fails closed because the stored report says 8 standalone and 4 shared-shell checks while the current suites report 10 and 6. Run npm run ai:time-steps-judge -- --url=http://127.0.0.1:8787/phrase only when a real loopback model is available; do not edit the report by hand.

Check the machine setup with npm run time-steps:judge-runtime. It currently reports that the local model files and proxy are absent.

See the complete gate summary

Run npm run time-steps:release-summary for one JSON record of technical-preview readiness and every open native, judge, and platform gate.

For a strict public-release decision, run npm run time-steps:broad-release-gate. It must fail until every broad-release gate is actually closed.

Check the Android machine with npm run time-steps:android-host. It reports connected targets, installed AVDs, and KVM access.

One safe review path

  1. Read this page and the decision report so the limits are clear.
  2. Open the Time Steps app and use only the fictional task in the reviewer guide.
  3. Change one assumption, try an invalid value, and check that the result updates or is refused clearly.
  4. If you are an authorized reviewer, use the separate native handoff for Android or macOS/iOS work.
  5. Record observations in the private reviewer form. Keep the downloaded response outside this repository.

This path asks what happened in one fictional run. It does not ask for a diagnosis, private story, real appointment, or proof that the product helps anyone.

Do not claim

  • That it helps every neurodivergent person.
  • That it improves punctuality, reduces stress, or improves health.
  • That it has passed native Android or iOS use.
  • That static accessibility checks prove accessibility benefit.
  • That an unsigned APK is ready for public distribution.
Open gates: authorized Android target, macOS/Xcode iOS run, release-owner signing, and approved human review. Automated checks cannot close these gates.
