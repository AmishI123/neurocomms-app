Product decision

Build the three-step flow: capture the interrupted task, choose the smallest restart step, and optionally set a short-lived prompt. The prompt is off by default. Data stays on the device.

Core experience

CaptureOne optional “What were you trying to do?” field. No diagnosis, employer, or mood fields.
Smallest stepThree editable suggestions; user can replace, skip, or reject them.
Bounded promptOff by default; none, 10m, 25m, or custom up to 24h. No recurring notifications.
Quiet completionDone, snooze, or abandon without streaks, scores, or failure states.

Privacy contract

Local-onlyNo accounts, cloud sync, analytics, social import, remote scripts, or model calls.
ReversiblePer-item delete, clear all, undo, and export before deletion.
Visible retentionSeven-day default for unfinished items; editable and explained at capture.
Stop conditionsRevise if deletion is hard to find, prompts recur without consent, or data leaves the device.

Acceptance gates

  1. Eight scripted scenarios pass: interruption, initiation freeze, low energy, sensory load, workplace privacy, deletion/undo, expiry, and no-network operation.
  2. Every scenario produces a JSON result; static audit finds no network or telemetry call.
  3. A browser smoke run completes capture → step → optional prompt → save in three decisions and under 60 seconds.
  4. All user-facing copy preserves skip, snooze, delete, and “if useful” choices; no diagnosis or clinical claims appear.

Evidence boundary

This is a prioritization spec from a public, query-selected corpus and transparent phrase matching. It supports what to test next. It does not establish clinical benefit, safety, prevalence, or user preference. Participant validation remains required for high-confidence claims.
