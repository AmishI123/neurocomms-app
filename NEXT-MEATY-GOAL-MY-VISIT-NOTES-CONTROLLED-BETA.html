CONTROLLED BETA · ENGINEERING USE

My Visit Notes

A small, reversible beta process for checking saving, privacy, recovery and follow-up work.

Current decision: run web-only engineering beta; hold native expansion.
Native Android and iOS checks need a working target and must be recorded separately.

The question this beta answers

Can a person prepare, use, review and continue a fictional appointment note without losing work or accidentally showing private words?

This is a software safety check. It does not measure medical benefit or prove that the product helps everyone.

Entry conditions

  • Release hashes and the LLM gate pass.
  • The tester uses a fresh profile or dedicated native installation.
  • Only fictional notes are used.
  • The tester understands there is no automatic server copy or sending.
  • Web, Android and iOS results are kept separate.

Required beta tasks

  1. Prepare, save, close and reopen a visit.
  2. Choose one question and confirm private words stay hidden.
  3. Background and return without revealing the message.
  4. Save Partly answered with a private answer note.
  5. Save and reopen a follow-up draft.
  6. Prepare a new appointment from unfinished work.
  7. Preview, copy, export and restore selected content.
  8. Work offline, force a failed save and retry once.
  9. Check for duplicates or lost data.
  10. Install the next build over the test copy.

What to record

RecordValue
Case and buildNon-identifying case ID and exact build hash
SurfaceWeb, Android or iOS
DeviceBrowser, phone or simulator name and OS version
ResultsEach task as Pass, Fail or Not run
EvidenceScreenshot or log path without real note content
Next actionFix, rerun, monitor or close

When to stop

LevelMeaningAction
S0 stopPrivate words sent, data lost or unsafe updateStop, preserve backup and investigate
S1 blockerRequired task fails or duplicates dataDo not expand beta; fix and rerun
S2 importantConfusing flow or optional device feature failsFix or document a clear limit
S3 polishSmall wording, spacing or visual issueSchedule the improvement

Any suspected privacy leak, lost data or wrong restore stays at least S0/S1 until checked.

Rollback

  1. Stop using the affected build.
  2. Keep the log, build hash and original backup.
  3. Restore into a separate test installation.
  4. Confirm the data and privacy boundary.
  5. Block the build until the fix and full rerun pass.

LLM judge

The LLM may compare records with the rules, inspect screenshots and exact output, group issues and explain failures.

It may not turn Not run into Pass, infer native behavior, treat a pleasant screen as proof of usefulness, read real medical notes or approve after a privacy/data-loss failure.

Exit decision

Expand only after every run is recorded, S0/S1 issues are fixed and rerun, the LLM confirms the evidence matches the claim, and web/Android/iOS decisions are listed separately.

Possible outcomes: expand web only, expand Android only, expand both platforms, or hold.
