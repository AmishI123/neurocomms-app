# Help me get through the conversation

Status: engineering delivery complete. All 207 current-source checks and the 165-file extracted-release verification passed. Final archive identity is recorded in product-specs/my-visit-notes/releases/manifest.json and its matching releases/verification.json.

## Outcome

Let someone prepare what they want to say, show only their chosen words during a visit, ask for a pause or clarification, and return to private notes without losing their place or accidentally displaying other note content.

The existing app already has large questions, communication requests, personal answer notes, save/resume, follow-up and device transfer. This goal connects the visit tools through a deliberately limited display. It does not replace those tools or create another set of question states.

## Required delivery

1. Explicit selection and preview of questions and editable requests before showing them.
2. A separate conversation view showing one chosen item at a time, without the library, private notes, visit title, editing controls or other unchosen content.
3. Reachable, optional requests for time, clarification and written information, using wording the person can change before showing it.
4. Hide, pause and resume at the same selected question. Honest saved/unsaved messages, including write failure and changes in another tab.
5. Deliberate return to private note-taking, followed by a return to the selected question. Display choices must not silently include answer notes.
6. Return to the existing after-visit review and next steps. Showing a question does not mark it answered.
7. Detailed plain-language requirements, fictional journeys, an executive/conference HTML presentation with speaker notes, help, an evidence map and a verified downloadable release.

## Boundaries

No diagnosis-based presets, accounts, cloud transfer, automatic speech, medical advice or generated answers. No participant recruitment is required. Browser checks cannot establish usefulness, physical-phone behavior or screen-reader usability. This display is not a lock: a person holding an unlocked device can leave it and access other content.

## Finish line

Prove the selected-content boundary in the rendered page and keyboard path; complete the prepare/show/request/hide/resume/private-note/review journey; test offline use, narrow screens, enlarged text, interruption and failed saves; rerun existing checks; inspect the presentation and app screenshots; build and test the extracted release. Keep this goal active until each requirement has direct evidence.
